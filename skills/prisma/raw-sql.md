# Raw SQL — The Escape Hatch and Its Toll

Raw SQL is the right answer for anything the schema cannot express, and a liability for anything it can. The toll is fixed: no generated types, no extensions, no `@updatedAt`, and column names from the database rather than from your model.

## The Calls

| Call | Returns | Notes |
|---|---|---|
| `$queryRaw` | Array of row objects | Tagged template; parameters are bound, never interpolated |
| `$executeRaw` | Number of affected rows | For writes and DDL |
| `$queryRawUnsafe` / `$executeRawUnsafe` | Same | Takes a plain string plus a parameter array; "unsafe" is the accurate word |
| `$runCommandRaw` | Driver response | MongoDB only (→ `providers.md`) |

All four run through the same connection as the surrounding transaction when called on a `tx` client, and on a separate pooled connection when called on the root client — which is how a raw statement inside a transaction ends up unable to see the transaction's own uncommitted rows.

## Safe Interpolation

```ts
import { Prisma } from '@prisma/client'

const rows = await prisma.$queryRaw<{ id: string; total: Prisma.Decimal }[]>`
  SELECT id, total FROM "Order"
  WHERE "tenantId" = ${tenantId}
    AND status = ANY(${statuses})
  ORDER BY "createdAt" DESC
  LIMIT ${limit}
`
```

- The tagged template turns every `${}` into a bind parameter. String concatenation into `$queryRawUnsafe` is SQL injection with extra steps.
- Compose fragments with `Prisma.sql` and join lists with `Prisma.join`:

```ts
const where = ids.length
  ? Prisma.sql`WHERE id IN (${Prisma.join(ids)})`
  : Prisma.empty
await prisma.$queryRaw`SELECT * FROM "User" ${where}`
```

- `Prisma.raw` injects text verbatim — the only legitimate use is an identifier (a column or table name) that must come from an allowlist you control:

```ts
const SORTABLE = { createdAt: '"createdAt"', total: '"total"' } as const
const column = SORTABLE[input] ?? SORTABLE.createdAt      // allowlist, never user text
await prisma.$queryRaw`SELECT * FROM "Order" ORDER BY ${Prisma.raw(column)} DESC`
```

- Bind parameters cannot be identifiers or keywords in any SQL engine. If you find yourself wanting `${}` around a table name, you want the allowlist above.
- Parameter count is capped by the engine (PostgreSQL: 65,535). A `Prisma.join` over a 100,000-element array fails; chunk it.

## What Comes Back

- The generic on `$queryRaw<T[]>` is an **assertion**, not a validation: nothing checks that the database agreed. Wrong shape means undefined at runtime with a green type check. Validate with a schema library at the boundary if the query is not trivial.
- Column names are database names. With `@map`, a model field `createdAt` may arrive as `created_at` — alias in the SQL (`SELECT created_at AS "createdAt"`) so the rest of the code does not care.
- Type mapping surprises worth knowing before they reach JSON:
  - PostgreSQL `COUNT(*)` returns `BigInt`, which `JSON.stringify` throws on. Cast in SQL (`COUNT(*)::int`) or convert on the way out (→ `typescript.md`).
  - `NUMERIC`/`DECIMAL` arrives as `Prisma.Decimal`, not a number.
  - `JSON`/`JSONB` arrives parsed; `UUID` as a string; `BYTEA` as bytes, not base64.
- Empty results are `[]`, never `null`. `$executeRaw` returns the affected-row count, so a "successful" update of zero rows is a `0` you must check.

## TypedSQL

`prisma >=5.19` generates types from real SQL files instead of trusting an assertion:

```sql
-- prisma/sql/topAuthors.sql
SELECT u.id, u.name, COUNT(p.id)::int AS "postCount"
FROM "User" u JOIN "Post" p ON p."authorId" = u.id
WHERE p."createdAt" > $1
GROUP BY u.id ORDER BY "postCount" DESC LIMIT $2;
```

```ts
import { topAuthors } from '@prisma/client/sql'
const rows = await prisma.$queryRawTyped(topAuthors(since, 10))   // typed args, typed rows
```

Generated by `prisma generate --sql` against a live database, so the types come from the engine's own analysis. This is the default choice for any raw query that ships — it converts the assertion above into a compile-time check.

## What Raw Bypasses

Everything the client would have done for you:

- `@default` and `@updatedAt` are client-side: a raw `UPDATE` leaves `updatedAt` stale, silently, forever (→ `schema.md`).
- Client extensions and middleware never see raw queries: soft-delete filtering, tenant scoping and audit logging all miss them (→ `extensions.md`).
- No relation loading, no nested writes, no type narrowing.

Consequence, and the workable line: raw for reads and analytics, client for writes that other code reads back. When a raw write is unavoidable, set the metadata columns yourself in the SQL and write a test that proves it.

## When Raw Is Correct

| Need | Why the client cannot |
|---|---|
| Window functions, `LATERAL`, recursive CTEs | No API surface |
| `DISTINCT ON`, first-row-per-group | `distinct` deduplicates after the limit (→ `queries.md`) |
| Bulk upsert | Prisma has no bulk `upsert` |
| `SELECT ... FOR UPDATE [SKIP LOCKED]` | No row-lock API (→ `transactions.md`) |
| Full-text and trigram search | Preview-only, and the index types are not expressible |
| Approximate counts from database statistics | Not modeled |
| `EXPLAIN`, index maintenance, DDL | Out of scope by design |

Bulk upsert, the pattern worth memorizing:

```ts
await prisma.$executeRaw`
  INSERT INTO "Metric" ("key", "value", "updatedAt")
  SELECT * FROM UNNEST(${keys}::text[], ${values}::int[], ${stamps}::timestamptz[])
  ON CONFLICT ("key") DO UPDATE SET "value" = EXCLUDED."value", "updatedAt" = EXCLUDED."updatedAt"
`
```

One statement, one round trip, no race, and `updatedAt` written explicitly because raw does not do it for you.

## Keeping Raw Honest

- Every raw query gets a test against a real database. Types will not catch a renamed column; a test will (→ `testing.md`).
- Prefer a database view for a raw read used in more than one place: it is versioned in a migration and can be introspected.
- Raw DDL belongs in migrations (`prisma db execute --file`), never in application startup (→ `migrations.md`).
- Grep for `Unsafe` in review. Every occurrence needs a one-line comment naming the allowlist that makes it safe.
