# Problem Subjects — Math, Physics, Chemistry, Code

The exam task in these courses is generation under time: pick the method, execute it, show the work. Practice must converge on that task, not on recognizing solutions.

## The Acquisition Ladder

1. **Worked example with self-explanation**: cover each step, predict it, uncover, compare. Novices learn more from studying solutions this way than from struggling cold (the worked-example effect, Sweller) — cold struggle is for later, not first contact.
2. **Faded practice**: solve the last step of a worked problem, then the last two, until full solo.
3. **Solo criterion**: 2-3 correct unassisted solves (Rule 4). Unassisted = no peeking, no formula sheet the exam won't provide.
4. **Interleave**: mixed sets across problem types — the exam's real skill is method selection (Rohrer, Rule 4). Blocked practice after acquisition feels better and transfers worse.

## The Error Log

One line per miss: problem ID · error type · fix. Reread the log before every practice set.

| Error type | Meaning | Fix |
|---|---|---|
| Concept | Didn't know the idea | Back to worked examples for that type |
| Selection | Right ideas, wrong method chosen | More interleaving; add "which method and why" drills |
| Setup | Right method, wrong translation of the problem | Translate-only drills: set up 5 problems, solve none |
| Execution | Algebra/arithmetic slip | Slow the written steps, add a check step; not more content |

Same error type recurring across sets is a targeting signal; scattered types under time pressure is a pacing signal (`test-day.md`).

## Recognition vs Generation

- "I understand the solutions but can't start problems" = recognition masquerading as skill. Fix: cover-and-solve from a blank page; only unassisted completions count (SKILL.md Traps).
- After the first worked examples per type, marginal reading is worth less than marginal solving — every additional solution read past that point is comfort, not practice.

## Timed and Constrained Practice

- Per-question budget (`test-day.md`) applies from the FIRST mixed set, not just mock exams.
- Match exam constraints exactly: calculator model, formula sheet, open/closed book. Practicing with a tool the exam removes trains a dependency.
- Show-your-work courses: practice writing the steps that earn partial credit. A correct answer with skipped steps trains the wrong artifact.

## Code and CS

- Rebuild small programs from memory after studying them; retyping from reference is transcription, not practice.
- Explain each line's purpose aloud (self-explanation); predict output before running — the prediction is the retrieval act.
- Algorithms: implement from the idea, not from the book's code; trace edge cases by hand before trusting the mental model.
- Paper exams: practice writing code on paper — the absent autocomplete and compiler is the exam's actual difficulty.

## Derivations and Proofs

- Re-derive key results closed-book; memorizing endpoints fails the "show that" question.
- Ask the course which derivations are examinable verbatim — those move to the verbatim track (`memorization.md`); the rest need only the generating idea.
- Proof courses: for each theorem, log the one non-obvious move; the retrieval item is "what is the trick in proof X", not the full transcript.
